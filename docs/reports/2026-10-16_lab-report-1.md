### 2. Setting: root kinematics tools
These describe the measurement the agents operate on. No claim is made about which tool is better.

- KymoRod (Bastien et al. 2016): midline from the organ outline each frame; displacement along the midline by correlating windows between frames; REGR is its derivative. Built to keep working while the organ bends. Has a scriptable core. Shown mainly on hypocotyls
- PatchTrack (Henry et al. 2023): the user clicks midline points from the root tip; disks every 10 px are matched frame to frame with an affine warp; velocity fitted with a flexible logistic (Morris & Silk 1992). The rotation term lets it follow a bending root
- Chavarría-Krauser et al. 2008: optical flow gives a velocity for every pixel; a hand-drawn midline is tracked; REGR from segment length change, and curvature production rate along the root. Maps REGR across the width, so flank asymmetry is shown directly
- Krupař et al. 2026: PIVlab velocity on images registered to the tip; strain rate by Savitzky-Golay derivative; one-dimensional profile, no flank strain
- Quality control in these workflows is manual: Youssef et al. 2018, using KymoRod on roots, checked profiles by eye and removed unreliable ones and set the frame step by hand for slow roots; Platre et al. 2024 report roots lost (8 % in 60 min runs, 25 % in 12 h runs) but no automatic test of a measurement
- The checks used here come from kinematic relations in the same literature: flank REGR difference tied to the material curvature rate for a rod of constant width (Silk & Erickson 1978; Chavarría-Krauser 2006; Bastien et al. 2014)

### Synthesis
- The tools above return a profile. Whether that profile is trustworthy is decided by a person, by eye, after the run
- This project keeps the tracker fixed and adds the layer around it: deterministic checks that hold for any correct measurement of a rod, an agent that names the fault and picks a remedy from a fixed list or declines, and a scoring scheme with known truth on synthetic rods

## Draft proposal

### Problem
- A growing root is a slender rod that generates its own strain. Its axial strain rate sets elongation; the difference across the section sets the rate of bending
- The strain-rate field is measured by image correlation on time-lapse movies. A measurement can fail silently: drift, too large a displacement per frame, midline jitter, low texture, width change
- Goal: a multi-agent system that measures the field, tests each result against beam kinematics, repairs a failed measurement with a remedy from a fixed list or declines to report it, and audits the batch
- The course paper makes claims about agent behaviour only. The biology question (whether the growth zone rescales or reshapes under osmotic load) is the setting, not a claim of this project
- [ANDREW] one-sentence research question for the course paper

### Intended users
- [ANDREW] e.g. plant biologists running kinematics on many time-lapse movies

### Why an agent
- A fixed script or an optimizer always returns an answer. The claim to test: an agent can name the fault, choose a structurally different remedy, and decline to report an untrustworthy result
- Tested on held-out faults not used during development

### Tools and architecture
| Part | Type | Job |
| :-- | :-- | :-- |
| Dispatcher | LLM agent | Splits roots into root-by-window tasks, estimates cost, submits tracking jobs |
| Tracker and midline nets | Tools | Stage correction, midline, strain-rate field (Quantum Borland v1) |
| Checker | Deterministic code, no LLM | Rigid-body invariance, tip-displacement closure against the stage log, Euler-Bernoulli kinematics |
| Diagnostician | LLM agent | Names the fault behind a failed check, picks a remedy from a fixed list, or declines to report |
| Auditor | LLM agent | Reviews the batch, flags outlier roots, compares control with stressed, writes the report with provenance |

- Tool interface: typed actions (`request_info`, `apply_remedy`, `accept`, `decline`) validated and executed by the orchestrator
- Stopping: accept, decline, or a step limit of 8
- Human approval: any compute budget before jobs are submitted; any threshold change; any action that deletes or overwrites data
- Built so far: checker, diagnostician, orchestrator. Build order: dispatcher, then auditor. Cut in reverse order

### Evaluation
- Synthetic rods with prescribed velocity fields and injected faults (truth known); fixed non-growing roots (zero strain); a 12-16 root subset of the real movies for baselines and repeated runs; all roots once, unattended
- Metrics: strain-rate error against truth; diagnosis accuracy; false-accept rate; abstention precision and recall; agreement across repeated runs; failure rate, manual minutes and run time per root
- Outcome categories per rod: good report, false accept, correct decline, unnecessary decline, not reported. Labels set from a no-agent sweep before any agent runs
- Baselines: fixed-parameter script, rule-based remedy tree, single-agent version; parameter search if time allows

### Major risks
- The diagnostician does not yet perform: 1 of 5 correct outcomes and 0 of 5 faults named on the first runs (commit 8177f96)
- Course staff may not count typed actions as tool use; MCP is blocked by organization policy
- Real movies have no ground truth for the strain-rate field; tip closure constrains the integral of the strain rate, not its shape
- The lab compute server is shared; jobs are capped. Cluster cost is not estimated yet
- Kinematics only: no stress, stiffness or constitutive law
