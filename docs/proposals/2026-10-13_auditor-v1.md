# Auditor v1: view, rule auditor, LLM auditor

From: build account, auditor-v1 session. Date: 2026-10-13. Spec `docs/specs/2026-10-13_auditor-v1-real-frame-quality-labels.md`, Task A. Written and committed before the rule auditor or any LLM auditor run.

## Batches
- A batch: the final records of one method on one set of `results/2026-10-12b_scored_v1/`. 8 batches: 4 methods x (dev 25 runs, held-out 15 runs)
- Final records: the cached tracker outputs the scored runs used, at each run's final settings (`scripts/synth/scored_v1.py`, `ScoredRunner` without remote). All 160 are in the cache. No tracker runs

## A1. View (`audit/view.py`, no LLM)
- Per run: `run_id`, `status` (accept, decline, not_reported = step_limit or error), `final_checks` (check, value, threshold, unit, passed), `remedies_kept` (changes not rolled back), `roll_backs`, `steps`, `final_settings`, `summaries`
- Summaries, window means over frame pairs (a grid point counts where at least half the pairs are finite, as `measure/info.py`):
  - `centre_peak_regr_pct_per_h`, `centre_peak_at_um`: peak of the centre strain rate and its distance from the tip
  - `growth_zone_length_um`: length of the contiguous stretch around the peak where the centre strain rate is above 10 % of the peak
  - `flank_difference_max_pct_per_h`, `flank_difference_at_um`: largest |plus - minus| flank strain rate, signed, and its position
  - `width_free_ratio_max`, `width_free_ratio_at_um`: largest |width-free ratio| (`measure/info.py`), signed, and its position; only when the width-free ratio is reported
- Built from an allow-list of summary keys. Withheld: fault, size, seed, label, truth, error before and after, category, correct, good, named fault, decline reason, confidence, traces, initial checks, check detail text, method, commit, run file name
- Run ids `r01`.. in an order shuffled by a fixed key per batch, so the id does not show the fault order. Map in `results/2026-10-13_auditor_v1/id_map.json`, for scoring only
- Batch statistics: per summary, median and MAD over all runs of the batch with a value (accepted, declined and not reported); robust z = (x - median) / (1.4826 MAD). MAD 0: (x - median) / (1.2533 mean absolute deviation); both 0: z = 0. Fewer than 3 values: z null
- Test `tests/test_auditor.py`: real run summaries with every withheld field set to sentinel values; no withheld key and no sentinel reaches the view, the batch table or the task

## A2. Rule auditor (`audit/rule.py`, baseline)
- An accepted run is flagged if any final check failed (passed false), or if any summary has |robust z| > 3 in its batch. Every other accepted run is cleared
- A check that is not run (plane sections under the width-free ratio) is not a failure
- Declined and not-reported runs are not audited

## A3. LLM auditor (`audit/llm.py`, `agents/prompts/auditor.md`)
- Through `agents/orchestrator.py`, unchanged. The action set is built per batch and registered as `ACTION_SETS["auditor"]` at run time; `agents/actions.py` unchanged
- First view (task): number of runs, the accepted run ids, the batch table (per run: status, checks as [value, threshold, passed], steps, number of remedies kept, roll backs, width_free, each summary as [value, robust z]; batch median and MAD)
- Actions:
  - `request_info` (kind: `batch_table` | `run_record`; `run_id` for `run_record`): the table, or the full view of one run
  - `flag` (run_ids, reason, evidence): reason from `check_failed_but_accepted`, `summary_outlier`, `remedy_pattern`, `width_free_ratio_used`, `other`; evidence a list from the check names, the summary names, `remedies_kept`, `roll_backs`, `steps`, `final_settings`
  - `clear` (run_ids)
  - `report` (text), ends the task
- `flag` and `clear` take a list of run ids, not one: the dev script batch has 25 accepted runs and the step limit is 20. One reason and one evidence list per `flag`
- Only accepted runs can be flagged or cleared. `report` is refused as an invalid action while an accepted run is undecided (the orchestrator feeds the refusal back; two invalid steps in a row end the task as `error`). A later decision on a run replaces the earlier one
- Model `claude-opus-5-5`, Claude Code 2.1.293, effort high, max turns 3: as in freeze v2 and `config/models.yaml`. Step limit 20 per batch (`config/models.yaml`, was 30, never used)
- The method that made the batch is not shown

## A4. Runs and scoring

- Prompt developed on the 4 dev batches only. Then the prompt is committed, the commit recorded, and the 4 held-out batches run 3 times each with no change in between
- Score per batch, accepted runs only: false accepts flagged / false accepts; good reports flagged / good reports (false flags); `second_root` runs that applied `use_width_free_ratio` and accepted a good centre (alt_repair), flagged / runs, apart. Same for the rule auditor
