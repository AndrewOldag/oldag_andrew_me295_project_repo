## A. Cluster path: submit and forget (dispatcher, c027)
1. `scripts/retrack_queue.py`, two commands, both safe to rerun at any time:
   - `submit`: for a list of (window, settings tag) not in the cache: stage the frames each window needs (the window's frames only, not the whole root imgdir), in groups that keep the cluster folder under 30 GB; write one Slurm array per group (1 core; time limit 45 min for `register_frames`, 15 min otherwise); `sbatch --parsable`; record array ids in `staging/c027/queue.csv`; exit. Jobs write outputs to the cluster task folder
   - `fetch`: `sacct` state for every recorded array; pull finished outputs to storage and to the VM cache with md5 checks; mark failed tasks with their error; clear staged frames of a group only after all its outputs are md5-checked on storage, logged in `DELETED.log` (standing rule). If the link or master is down: print `connection down`, exit 0. Never wait, never retry in a loop
   - Tests with a fake relay: down link -> exit 0 and no state change; partial array -> only finished tasks pulled; md5 mismatch -> not cached
2. Wave 1 job list: for the 46 batch-2 windows the tree did not reach, every single remedy setting in the action schema applied to base settings (enumerate from `agents/actions.py`, not by hand), plus the moved copy where rigid invariance is computed. For the 38 reached windows, the same set minus what c026 already cached. Print the job count and the ledger's worst-case cost before submitting
3. Ledger: read the final c026 figure first (it could not be read on 14 Nov). Stop and Needs Andrew if the projected total since 2026-10-23 passes $15 (Andrew, 2026-11-20; was $12)
4. Cache miss in a run (a stacked remedy, or a setting not in wave 1): the window is paused, not waited on. Record `paused: needs <setting tag>` and go on to the next window. The missed settings go into the next `submit`. A paused window is rerun from step 0 once its tracks are cached; the paused trace stays in staging and is not scored (as for session-limit stops)
